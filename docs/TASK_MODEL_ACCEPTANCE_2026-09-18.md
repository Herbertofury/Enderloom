# Durable task model acceptance

PA-020 now uses versioned typed details in the existing `task_history` owner. No second job store or scheduler was introduced. Records preserve operation/target, parent/children, immutable attempt identities and outcomes, exact checkpoint digest, cancellation request, blocker/recovery explanation, run/process references, canonical produced evidence and domain-owned cleanup receipts. Older records retain explicit gaps in their history; migration does not invent processes, prior attempts or source evidence.

Resume retains the same task ID and appends an attempt. Cancellation reaches descendants and prevents new children of an already cancelled parent. Exact run IDs and PID observations are historical evidence, never permission to terminate a possibly reused PID after restart. Owned resources become `needs_review` after an interrupted worker; existing domain cleanup validates the actual sandbox. Clear finished archives settled records so evidence and task links still resolve, and leaves unresolved cleanup visible. `get_task_detail`, CLI `task show`, and the expandable activity panel share this owner.

Conversion intake links its immutable snapshot and source inventories. Paired startup captures form a real parent/child graph. Startup captures and Testing Lab record their generated sandbox, run identities and observed Minecraft/recorder processes; analysis attaches canonical evidence. Supported safe replay remains mod inspection and conversion intake. Other operations retain an explicit no-safe-checkpoint recovery explanation instead of blindly replaying an install, launch or mutation. PA-021 supplies the broader transaction model separately.
